货记系统总体设计说明书 V1.0
1. 系统定义
1.1 产品定位
货记是一套面向GPU服务器、整机、模组及零配件贸易产业链的：
AI货源记录、关系管理、报价协作与交易推进系统。
产品由两个终端、两个版本组成：
终端
个人版
企业版
微信小程序
随手记货、查货、报价、跟进
团队录入、项目执行、审批、现场验货
Web网页端
批量管理、分析个人货源
企业货源、客户、项目、报价、权限和经营管理
1.2 核心系统原则
一个账号可以同时拥有个人空间和多个企业空间。
所有业务数据必须归属于一个工作空间。
个人数据和企业数据在数据库层面隔离。
个人共享给企业的数据采用“共享镜像”，不允许企业直接读取个人原始数据。
市场货源和企业实际库存必须分开管理。
AI负责整理和提示，用户负责最终确认。
所有价格、数量、状态变化必须保留历史。
企业敏感字段必须支持字段级权限和脱敏。
小程序解决高频现场动作，网页端解决复杂管理动作。
第一阶段采用模块化单体架构，不直接上微服务。

2. 系统业务边界
2.1 系统负责
文本、截图、照片、语音记货
AI识别服务器配置和商务条件
市场货源管理
企业实际库存管理
求购需求管理
货主、渠道商、居间商、买家关系管理
货源可信度与证据管理
重复货源识别
货源与需求匹配
价格、数量、交期更新
报价生成、审批和发送
交易项目推进
跟进任务和提醒
现场验货
合同、付款、交付基础管理
利润和佣金记录
企业权限和审计
2.2 第一阶段不负责
公开服务器交易广场
平台资金托管

自动判定货源绝对真假
系统只能由用户主动粘贴、上传、转发或拍摄信息，不能承诺直接抓取微信私人聊天。

3. 总体技术架构
3.1 架构选型
第一阶段采用：
模块化单体业务服务 + 独立AI处理服务 + 异步任务队列。
不建议第一版拆成十几个微服务。
原因：
初期业务规则变化频繁
模块间事务较多
团队开发和运维成本更低
后期可以按模块独立拆分

4.1 前端
微信小程序
推荐两种方案：
优先：微信原生小程序
多端要求明确时：Taro
第一阶段更建议原生小程序，减少上传、拍摄、扫码、分享和微信登录兼容问题。
Web网页端
建议：
React

TypeScript
企业级组件库

推荐：
TypeScript + NestJS，或Java + Spring Boot

PostgreSQL主数据库
Redis缓存及分布式锁
对象存储保存图片、视频、文件
消息队列处理AI、通知、索引和水印任务

初期可以先用PostgreSQL全文检索和pgvector

数据库主从或托管高可用

6.3 权限模块 Permission
采用：
RBAC角色权限 + 数据范围 + 字段权限 + 数据密级。
权限判断分四层：
用户是否属于当前工作空间
用户是否具有操作权限
用户是否有权访问当前记录
用户是否有权查看当前字段
权限表达：
CanAccess =  IsWorkspaceMember  AND HasActionPermission  AND MatchDataScope  AND PassRecordPolicy

两者不能使用同一库存字段混合管理。

12. AI处理流程
sequenceDiagram    participant U as 用户    participant C as 小程序/Web    participant API as 核心API    participant Q as 任务队列    participant AI as AI服务    participant DB as 数据库    U-&gt;&gt;C: 上传文字/图片/语音    C-&gt;&gt;API: 创建CaptureItem    API-&gt;&gt;DB: 保存原始记录    API-&gt;&gt;Q: 提交AI任务    API--&gt;&gt;C: 返回处理中状态    Q-&gt;&gt;AI: 执行OCR/ASR/结构化    AI-&gt;&gt;AI: 标准化配置    AI-&gt;&gt;AI: 检测缺失和冲突    AI-&gt;&gt;AI: 重复货源初筛    AI-&gt;&gt;DB: 保存抽取结果    C-&gt;&gt;API: 查询处理结果    API--&gt;&gt;C: 返回待确认字段    U-&gt;&gt;C: 确认或修正    C-&gt;&gt;API: 创建正式货源    API-&gt;&gt;DB: 保存货源和版本
AI任务必须异步执行，前端不能一直阻塞等待。

30. 最终架构判断
货记的核心不是“做一个服务器CRM”，而是建立一套从非结构化市场信息进入正式交易的标准数据链路：
聊天、截图、语音→ 原始采集记录→ AI结构化→ 用户确认→ 动态货源→ 证据与可信度→ 求购匹配→ 报价→ 交易项目→ 验货→ 合同付款→ 交付验收→ 库存和经营数据
个人版和企业版共享同一底座，但解决不同的问题：
个人版保护和管理个人的货源、人脉及交易机会。
企业版把明确进入企业空间的货源、客户和项目沉淀为公司资产。
小程序承担即时输入、现场执行和快速沟通。
Web网页端承担批量管理、权限、流程和经营决策。
第一阶段最重要的不是把所有企业功能一次做完，而是把以下三个底座做对：
工作空间和数据归属。
动态货源数据模型。
AI输入到正式货源的确认链路。
这三个底座一旦做错，后面企业权限、交易项目和数据资产都会推倒重来。
