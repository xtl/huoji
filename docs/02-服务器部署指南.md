# 货记服务器部署指南

本文档用于把当前 Web 版货记部署到一台已安装 Docker 的云服务器。

## 1. 云服务器控制台

先确认安全组或防火墙已开放：

- `22`：SSH 登录
- `80`：HTTP 访问
- `443`：HTTPS 访问

开发端口如 `5176` 不需要开放到公网。

## 2. 登录服务器

在本机终端执行：

```bash
ssh root@你的服务器公网IP
```

如果云厂商给的是 Ubuntu 普通用户，则使用：

```bash
ssh ubuntu@你的服务器公网IP
```

## 3. 安装基础工具

容器镜像服务器通常已经有 Docker。登录后先检查：

```bash
docker version
docker compose version
```

如果缺少 Git：

```bash
apt update
apt install -y git
```

## 4. 拉取代码

```bash
mkdir -p /opt/huoji
cd /opt/huoji
git clone 你的代码仓库地址 .
```

如果暂时还没有远程 Git 仓库，也可以先用压缩包或 `scp` 上传项目目录。

## 5. 配置生产环境变量

```bash
cp .env.production.example .env.production
nano .env.production
```

云同步版助手连接 `https://huoij.com`。将域名指向运行 Caddy 的服务器，在 `.env.production` 填入以下配置和已开通的短信服务凭据。

```env
APP_HOST=huoij.com
APP_URL=https://huoij.com
ACME_EMAIL=你的邮箱
SMS_PROVIDER=aliyun
HUOJI_PLATFORM_ADMIN_PHONES=已获授权的手机号
```

也可以把管理员名单单独写入服务器上的 `.env.platform`，变量名为 `HUOJI_PLATFORM_ADMIN_PHONES`，多人用英文逗号分隔。Compose 2.24 及以上会在文件存在时载入该名单。平台管理员通过 `https://huoij.com/platform` 单独验证手机号，在「平台密钥」测试、保存或轮换 DeepSeek API Key。个人及已认证企业的 AI 解析均使用这把密钥。

在「Token 用量」选月份，可以按使用账号查看各空间用量，也可以按企业查看成员用量。两种视图存在重叠。月限额作用于对应账号的所有调用或整家企业的调用。填 0 暂停，留空取消限额。达到限额后拦截新调用，已发出的请求仍会结算。缺少服务商回执的调用列为待核对。历史自有密钥用量保留在原空间的账本。

启用企业人工审核时，在服务端环境变量 `ENTERPRISE_REVIEWER_IDS` 填入指定平台审核员的货记用户 ID，多人用英文逗号分隔。审核员使用自己的个人空间打开「企业工作台」，核验企业主体、申请人授权及申报的邮箱域名后作出审核结论。申请人不能审核自己的申请。

企业邮箱邀请使用 `RESEND_API_KEY` 和 `ENTERPRISE_MAIL_FROM`，后者填写在发件服务中已验证的地址。手机号邀请显示在受邀账号的「企业工作台」。正式运营前应启用真实短信登录。用量按北京时间自然月及模型回传的 Token 统计，账本与认证资料保存在持久化数据目录的 `enterprise.sqlite`。

### 货记分与支付

充值按 1 元兑 200 分。个人月卡 28 元，每月 5,600 分。个人年卡 336 元，含 3 个月额外积分，共 84,000 分，分 12 期、每期 7,000 分到账。续购会员从已有权益期满起算，月末周年按北京时间当月最后一天处理。服务每分钟检查到期发分，服务重启、查看钱包或开始解析也会补记已到期的期数。

服务端收到支付宝验签通过且金额匹配的支付成功通知后，按订单保存的权益向下单空间入账。配置支付宝商户并开放异步回调地址后，可在收银台进行真实收款验收。钱包、预留额度、会员发放计划和积分流水随 `enterprise.sqlite` 持久化；备份时一并保留支付订单。

个人和企业空间分别结算。AI 解析按 DeepSeek 人民币模型费用每 1 元扣 560 分，固定精度记账。平台后台按账号和企业展示已核算模型费用与实扣积分。模型与峰谷单价依据 [DeepSeek 官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)；当前计费日历覆盖 2026–2027 年，价格调整或公布下一年度节假日时更新 `demo_ui/server/model-credit-prices.ts`。

## 6. 启动服务

```bash
docker compose --env-file .env.production -f compose.prod.yml up -d --build
```

查看状态：

```bash
docker compose --env-file .env.production -f compose.prod.yml ps
docker compose --env-file .env.production -f compose.prod.yml logs -f web
```

验证公网 HTTPS 和助手连接协议。第二个接口应返回 `syncVersion: 1`、`aiBilling: "platform"` 和 `loginReady: true`。随后用真实手机号完成短信登录以验证短信投递。

```bash
curl --fail https://huoij.com/api/health
curl --fail https://huoij.com/api/cloud/capabilities
```

## 7. 后续更新

以后代码有更新：

```bash
cd /opt/huoji
git pull
docker compose --env-file .env.production -f compose.prod.yml up -d --build
```

## 8. 采集数据和持久化

用户从云同步版助手登录，切换到目标空间、选择群并开始采集。助手在本机识别微信消息，将待上传记录保存在本地队列，收到服务端确认后标记为已送达。其他浏览器以同一账号进入同一空间，即可查看已同步的消息及已入库的供需记录。旧本机测试包的历史资料需要另行迁移。

服务端使用 Compose 挂载的 `/app/.data` 持久化账号、采集记录、供需库、企业与 Token 账本以及加密密钥文件。备份和恢复需覆盖整个数据卷。若配置了 `HUOJI_DEEPSEEK_MASTER_KEY`，恢复时需使用同一把主密钥。

## 9. 接入阿里云验证码 2.0

阿里云验证码 2.0 是获取短信前的人机验证，用来防止短信接口被刷。它不会发送短信，短信发送仍由 `SMS_PROVIDER` 指定的短信服务商负责。

先在阿里云控制台完成：

- 开通验证码 2.0
- 在概览页获取身份标 `prefix`
- 新建 Web/H5 验证场景，获取场景 ID
- 创建 RAM 子账号 AccessKey，并授予验证码 2.0 服务端验签权限

然后编辑服务器环境变量：

```bash
cd /opt/huoji
nano .env.production
```

修改为：

```env
CAPTCHA_PROVIDER=aliyun
ALIYUN_CAPTCHA_REGION=cn
ALIYUN_CAPTCHA_PREFIX=你的验证码身份标
ALIYUN_CAPTCHA_SCENE_ID=你的验证码场景ID
ALIYUN_CAPTCHA_ACCESS_KEY_ID=你的阿里云AccessKeyId
ALIYUN_CAPTCHA_ACCESS_KEY_SECRET=你的阿里云AccessKeySecret
ALIYUN_CAPTCHA_ENDPOINT=captcha.cn-shanghai.aliyuncs.com
ALIYUN_CAPTCHA_MODE=popup
```

保存后重启：

```bash
sudo docker compose --env-file .env.production -f compose.prod.yml up -d --build
```

启用后，用户点击“获取验证码”会先完成阿里云验证码 2.0，后端调用 `VerifyIntelligentCaptcha` 验签通过后，才会继续发送短信。

## 10. 接入阿里云短信验证码

阿里云短信服务负责真正发送 6 位短信验证码。先在阿里云控制台完成：

- 开通短信服务
- 申请并审核通过短信签名
- 申请并审核通过验证码短信模板，取得模板 Code，例如 `SMS_123456789`
- 创建 RAM 子账号 AccessKey，建议只授予 `dysms:SendSms` 权限

然后编辑服务器环境变量：

```bash
cd /opt/huoji
nano .env.production
```

修改为：

```env
SMS_PROVIDER=aliyun
SMS_RESEND_COOLDOWN_SECONDS=60

ALIYUN_SMS_ACCESS_KEY_ID=你的 AccessKeyId
ALIYUN_SMS_ACCESS_KEY_SECRET=你的 AccessKeySecret
ALIYUN_SMS_SIGN_NAME=你的短信签名
ALIYUN_SMS_TEMPLATE_CODE=你的模板Code
ALIYUN_SMS_ENDPOINT=dysmsapi.aliyuncs.com
```

短信模板变量名要和控制台审核通过的模板一致：

```env
# 模板包含 ${code}
ALIYUN_SMS_TEMPLATE_PARAMS=code

# 模板包含 ${code} 和 ${ttl}
ALIYUN_SMS_TEMPLATE_PARAMS=code,ttl
```

保存后重启：

```bash
sudo docker compose --env-file .env.production -f compose.prod.yml up -d --build
sudo docker compose --env-file .env.production -f compose.prod.yml logs --tail=80 web
```

浏览器退出登录后重新获取验证码。如果阿里云返回模板不匹配、签名未审核、余额不足等错误，接口会把错误信息返回给前端和日志，按错误码处理即可。

## 11. 可选：接入腾讯云短信验证码

当前服务也支持腾讯云短信。先在腾讯云控制台完成：

- 开通短信服务
- 创建短信应用，取得 `SmsSdkAppId`
- 申请并审核通过短信签名
- 申请并审核通过验证码短信模板
- 创建腾讯云访问密钥，建议使用只允许短信 `SendSms` 的子账号密钥

然后编辑服务器环境变量：

```bash
cd /opt/huoji
nano .env.production
```

修改为：

```env
SMS_PROVIDER=tencentcloud
SMS_RESEND_COOLDOWN_SECONDS=60

TENCENTCLOUD_SECRET_ID=你的 SecretId
TENCENTCLOUD_SECRET_KEY=你的 SecretKey
TENCENT_SMS_SDK_APP_ID=你的短信应用 ID
TENCENT_SMS_SIGN_NAME=你的短信签名内容
TENCENT_SMS_TEMPLATE_ID=你的短信模板 ID
TENCENT_SMS_REGION=ap-guangzhou
TENCENT_SMS_ENDPOINT=sms.tencentcloudapi.com
```

短信模板变量顺序要和控制台审核通过的模板一致：

```env
# 模板只有 {1}=验证码
TENCENT_SMS_TEMPLATE_PARAMS=code

# 模板为 {1}=验证码、{2}=有效分钟数
TENCENT_SMS_TEMPLATE_PARAMS=code,ttl
```

保存后重启：

```bash
sudo docker compose --env-file .env.production -f compose.prod.yml up -d --build
sudo docker compose --env-file .env.production -f compose.prod.yml logs --tail=80 web
```

浏览器退出登录后重新获取验证码。如果腾讯云返回模板不匹配、签名未审核、余额不足等错误，接口会把错误信息返回给前端和日志，按错误码处理即可。
