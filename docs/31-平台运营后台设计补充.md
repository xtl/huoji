# 第 31 章（补充）：平台运营后台设计

> 本章为《货记系统总体设计说明书 V1.0》的补充章节。
> V1.0 覆盖了企业租户自身的后台（第 7.4 章企业版网页端），但未定义**平台运营方**的管理能力。
> 货记是多租户 SaaS，说明书中已隐含多处依赖平台侧操作的设计：
> `workspaces.plan_code`（套餐）、`workspaces.status=SUSPENDED`（封停）、
> `ai_extraction_jobs.cost_amount`（AI 成本）、6.1 章"账号禁用"、24.3 章运营侧监控指标。
> 本章补齐这一缺口。整理日期：2026-07-22。

## 31.1 定位与边界

平台运营后台服务于**平台运营方内部人员**（运营、客服、合规、管理员），与业务端完全隔离：

- 独立入口、独立域名/路径（如 `admin.huoji.example` 或 `/platform`），不与业务 Web 共用登录态
- 独立账号体系 `platform_admins`，**不复用**业务侧 users / workspace RBAC —— 业务 RBAC 是 workspace 内权限，平台管理员是跨 workspace 权限，二者模型不同，禁止混用
- 平台侧一切操作写入独立的 `platform_audit_logs`，不可删除

### 数据可见性红线

运营人员默认**不可见**租户业务敏感数据：成本价、底价、佣金、完整 SN、聊天原文、合同文件。
可见范围仅限：账号与空间元数据、内容处置所需的被举报对象、脱敏后的统计数据。
特殊排查需要提权查看时，必须双人审批 + 留痕（三期实现，一二期直接禁止）。

## 31.2 分期实施

### 一期：管理 API + 现成 BI（不做界面）

- `platform_admins` 表 + 独立鉴权（用户名密码 + TOTP，或内部 SSO）
- 三个最小管理 API：
  - `POST /platform/users/{id}/disable` / `enable` —— 账号封禁
  - `POST /platform/workspaces/{id}/suspend` / `resume` —— 空间封停
  - `POST /platform/contents/takedown` —— 下架货源/文件/采集内容（小程序过审与投诉处置的硬要求）
- `platform_audit_logs` 落库
- 指标看板用 Grafana/Metabase 直连只读库：注册量、DAU、AI 调用量与成本、任务队列积压、OCR 失败率

### 二期：正式运营后台（Web 控制台）

- 用户/企业管理：搜索、详情、禁用、企业认证审核
- 套餐管理：plan_code 分配与变更（免费/内测/付费）
- 内容处置流程：举报队列、处理动作、处理记录
- AI 成本看板：按空间/模型/日期聚合（数据源 ai_extraction_jobs）
- 客服支持视角：查空间状态、最近错误，遵守 §31.1 数据红线

### 三期：商业化

- 计费与订阅：套餐购买、续费、发票
- 运营分析：留存、活跃、转化漏斗
- 公告/消息推送管理、灰度开关（feature flag）管理

## 31.3 核心表

```sql
platform_admins
- id UUID PK
- username varchar UNIQUE
- password_hash varchar
- totp_secret varchar
- role varchar            -- SUPER_ADMIN / OPS / SUPPORT / COMPLIANCE
- status varchar          -- ACTIVE / DISABLED
- last_login_at timestamptz
- created_at timestamptz

platform_audit_logs
- id UUID PK
- admin_id UUID NOT NULL
- action varchar          -- USER_DISABLE / WORKSPACE_SUSPEND / CONTENT_TAKEDOWN / ...
- target_type varchar
- target_id UUID
- reason text             -- 操作必须填写原因
- before_data jsonb
- after_data jsonb
- ip_address inet
- created_at timestamptz

content_moderation_records   -- 二期
- id UUID PK
- report_source varchar   -- USER_REPORT / PLATFORM_SCAN / REGULATOR
- object_type varchar     -- GOODS / FILE / CAPTURE / PARTY
- object_id UUID
- workspace_id UUID
- status varchar          -- PENDING / TAKEN_DOWN / REJECTED / RESTORED
- handled_by UUID
- handled_at timestamptz
- notes text
```

## 31.4 与业务端的交互约定

- 平台封停空间：业务 API 对该 workspace 全部请求返回 `WORKSPACE_SUSPENDED`，数据不删除
- 平台下架内容：业务对象增加 `takedown_at` / `takedown_reason` 字段（软下架），租户内不可见但保留证据
- 平台操作触发领域事件 `platform.user_disabled` / `platform.workspace_suspended` / `platform.content_takedown`，由通知服务告知相关租户管理员
