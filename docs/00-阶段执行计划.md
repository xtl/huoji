# 货记系统 · 阶段执行计划

> 依据《货记系统总体设计说明书 V1.0》第 25/26/29 章整理，并结合 `demo_ui` 原型核查结论。
> 本文件是开发排期的唯一依据；与说明书冲突时，以说明书的数据模型与约束（第 9/10/15/28 章）为准。

## 0. 总原则（说明书第 30 章）

一期必须做对的三个底座，做错则全部推倒重来：

1. **工作空间与数据归属**（workspace_id 强制、个人/企业空间隔离）
2. **动态货源数据模型**（货源 / 库存 / 报价三对象分离，价格·数量·状态留历史）
3. **AI 输入 → 用户确认 → 正式货源的确认链路**（CaptureItem 可追溯）

## 1. 一期：核心可用版本（现在做）

### 1.0 核心功能锁定（2026-07-24 更新）

一期产品先收敛为响应式 Web，兼容手机浏览器和桌面浏览器；微信小程序暂缓。

核心功能只做三大块：

| 模块 | 内容 | 一期边界 |
|---|---|---|
| 录入货源 | AI 解析货源、手工录入货源 | AI 结果必须经用户确认后入库；手工录入直接创建我的货源；品类先支持服务器、显卡、内存 |
| 我的货源 | 查看、搜索、改价、改数量、标记失效、发布到广场 | 这是私有资产库，敏感字段只在有权限时返回 |
| 广场 | 发布需求、发布货源、浏览供需 | 广场使用脱敏公开快照，不直接公开 goods_offers / demands 原表；分类固定为 品类 × 3×2：服务器/显卡/内存 × 现货/期货/租赁 × 供应/需求 |

新的主链路：

`AI/手工录入 → 我的货源 → 选择发布到广场 → 广场供需浏览与联系`

### 1.1 后端任务包

| 编号 | 内容 | 说明 |
|---|---|---|
| BE-01 | 身份与工作空间 | 微信/手机号登录、个人空间自动创建、空间切换、企业创建、成员基础模型 |
| BE-02 | 文件与采集 | 对象存储直传凭证、文件回调、capture_items、AI 任务提交与状态查询 |
| BE-03 | 货源 | CRUD、状态机、改价改数量（写历史表）、版本快照、乐观锁 |
| BE-04 | 联系人 | party / party_roles / party_relations、货源关联联系人 |
| BE-05 | 求购与匹配 | 求购 CRUD、基础规则匹配、候选列表（打分算法一期从简） |
| BE-05A | 广场发布层 | marketplace_posts 脱敏快照、发布货源、发布需求、广场列表；trade_mode 区分 SPOT/FUTURES/RENTAL，post_type 区分 GOODS/DEMAND |
| BE-06 | 跟进与通知 | tasks、提醒、站内通知、小程序订阅消息 |
| BE-07 | 报价（基础） | quote / quote_versions / quote_items、脱敏报价卡、PDF/图片输出（**审批留二期**） |
| BE-08 | 权限与审计（基础） | workspace 成员校验、字段级脱敏（无权字段后端不返回）、审计日志写入 |
| BE-09 | 平台管理 API（新增） | platform_admin 独立鉴权、封禁用户/封停空间/下架内容三个操作 + 平台审计（详见 docs/31） |

### 1.2 AI 任务包

- AI-01 OCR / ASR 适配层
- AI-02 货源结构化：固定 JSON Schema、字段置信度、缺失项、冲突项、意图识别（异步任务，禁止前端同步阻塞）
- AI-03 配置标准化：GPU/品牌别名、形态、单位、币种、地名归一
- 多模型网关设计（不写死单一供应商）+ 调用日志与成本入库（ai_extraction_jobs）

### 1.3 前端

- 小程序 MP-01 ~ MP-08 暂缓，不进入当前一期执行范围
- Web WEB-01 ~ WEB-06：在 `demo_ui` 交互稿基础上重构为响应式 Web（手机浏览器 + 桌面浏览器）
- Web 信息架构固定为：录入货源 / 我的货源 / 广场
- 一期新增页面：AI 确认页（逐字段置信度/缺失项）、价格历史、货源失效、报价 PDF 导出、基础搜索

### 1.4 一期明确不做

微信小程序 / 完整企业权限配置 / 完整审批流 / 验货 / 合同财务 / 经营驾驶舱 / 计费。
**但以下表结构一期必须建好**（说明书要求底层模型先行）：share_projections、roles/permissions、audit_logs。

### 1.5 一期验收标准（说明书第 26 章摘要)

- AI 记货：输入「H200超微8卡，深圳现货10台，430含税，三天交，老陈的货」→ 正确结构化 + 提示缺失（整机型号/SN/质保/税率）
- 货源：创建/查看/编辑/改价/改数量/状态变化/查历史/标记失效/生成报价
- 空间隔离：个人数据企业不可读、A/B 企业互不可见、共享只显示允许字段、撤销共享后停止同步、离职成员无法访问
- 报价：隐藏成本价与上游联系人、历史版本、有效期、图片或 PDF 输出

## 4. demo_ui 原型核查结论（改造清单）

`demo_ui` 定位为**高保真交互稿**，不是产品代码。信息架构（空间切换、AI 超级输入框、货源/求购/跟进/人脉）可保留；以下问题在 Web 正式版中必须修正：

| # | 问题 | 违反条款 | 处理 |
|---|---|---|---|
| 1 | ownerPrice/purchaseCost/expectedCommission 与对外价同对象全量下发前端 | 16.3 无权字段后端不得返回 | 后端按权限裁剪；前端类型拆分视图 |
| 2 | StockStatus(7态)/DealStage(12态) 与第 15 章状态机不一致，缺 DRAFT→PARSING→NEED_CONFIRMATION | 第 15 章 | 统一使用 packages/domain-types 中的枚举 |
| 3 | 创建求购时自动生成 Deal | 第 8/10.16 章（匹配=推荐+确认） | 去掉自动创建，改为 match_candidates 推荐 |
| 4 | 改价/改状态直接覆盖，无历史 | 第 28 章约束 6 | 走 price/quantity/version 历史表 |
| 5 | localStorage 持久化、无登录、无空间隔离 | 第 23.1 章 | 接入真实 API + 会话 |
| 6 | AI 直连 Gemini、供应商写死（含页脚文案） | 第 4.3 章多模型网关 | 走 ai-service 网关；清理演示文案 |
| 7 | 审批/审计为前端数组模拟 | 第 6.14/6.19 章 | 审批二期实现；审计一期后端落库 |

## 5. 关键开发约束（第 28 章，开发中不可变）

1. 每条业务数据必须有 workspace_id
2. 禁止跨空间直接查询；共享走镜像/投影
3. 货源、库存、报价是三个不同对象
4. 报价必须保存版本快照
5. 价格、数量、状态必须保留历史
6. AI 抽取结果必须经用户确认才能成为正式数据
7. 无权限字段后端不得返回
8. 所有文件走受控 File Service
9. 模块化单体，模块间仅通过明确 Service 或领域事件通信
